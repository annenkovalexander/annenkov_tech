# Ошибки и проблемы

### 1. Некорректная регистрация хука как плагина GSAP

- **Приоритет:** Medium
- **Тип:** подтверждённая ошибка
- **Что обнаружено:** Функция `useGSAP` из пакета `@gsap/react` передаётся в метод `gsap.registerPlugin()`.
- **Почему это важно:** `useGSAP` является React-хуком для управления жизненным циклом анимаций, а не плагином GSAP (такими как `MotionPathPlugin`). Метод `registerPlugin` предназначен исключительно для расширения функциональности ядра GSAP. Попытка зарегистрировать хук может привести к предупреждениям в консоли или некорректному поведению библиотеки.
- **Сценарий проявления:** При инициализации компонента и выполнении первой отрисовки.
- **Необходимые условия:** Запуск приложения с установленной библиотекой `gsap` и `@gsap/react`.
- **Как исправить или проверить:** Удалить строку с регистрацией хука `useGSAP`, оставив только регистрацию `MotionPathPlugin`.
- **Дословный фрагмент:**

```text
gsap.registerPlugin(useGSAP);
```

### 2. Хрупкая синхронизация позиционирования точек (Magic Timeout)

- **Приоритет:** Medium
- **Тип:** условный риск
- **Что обнаружено:** Использование цепочки из двух `requestAnimationFrame` и последующего `setTimeout` на 50 мс для запуска функции `repositionDots`.
- **Почему это важно:** Данный паттерн является "костылем" для ожидания фактического рендеринга SVG-пути в DOM. Если отрисовка или расчёт геометрии браузером займёт больше времени, чем 50 мс (например, при высокой нагрузке на CPU или медленном устройстве), точки будут позиционированы некорректно относительно пути.
- **Сценарий проявления:** При первой загрузке страницы или при изменении размеров окна (`viewPort`), что вызывает пересоздание `circlePathD`.
- **Необходимые условия:** Медленная отрисовка DOM или задержки в основном потоке исполнения JS.
- **Как исправить или проверить:** Вместо фиксированного тайм-аута использовать механизмы отслеживания готовности элементов или интегрировать расчеты непосредственно в жизненный цикл рендеринга GSAP через `useGSAP`.
- **Дословный фрагмент:**

```text
        firstFrame = requestAnimationFrame(() => {
            secondFrame = requestAnimationFrame(() => {
                timeout = setTimeout(repositionDots, 50);
            });
        });
```

## Ошибки и проблемы

### 1. Риск получения NaN при расчёте процента индекса точки

- **Приоритет:** Medium
- **Тип:** условный риск
- **Что обнаружено:** Функция `getPercentageByDotIndex` выполняет деление без проверки знаменателя на ноль.
- **Почему это важно:** Если массив точек пуст и `dotsLength` равен 0, результат функции будет `NaN`. Это может привести к некорректному рендерингу или ошибкам в CSS-свойствах (например, при передаче этого значения в `stroke-dasharray` или трансформации), что визуально «сломает» компонент.
- **Сценарий проявления:** При условии, что в приложении возникнет состояние, когда список событий/периодов пуст, и вызывающий код передаст `0` в качестве `dotsLength`.
- **Необходимые условия:** Передача `dotsLength = 0` в функцию.
- **Как исправить или проверить:** Добавить проверку на ноль или возвращать `0`, если `dotsLength <= 0`.
- **Дословный фрагмент:**

```text
export const getPercentageByDotIndex = (dotIndex: number, dotsLength: number): number => 
    dotIndex / dotsLength;
```

## Ошибки и проблемы

### 1. Риск приведения типов при получении данных из API

- **Приоритет:** Medium
- **Тип:** условный риск
- **Что обнаружено:** Для идентификаторов используется брендированный тип `UUID`, который объединяет шаблонную строку и специальный флаг `__brand`.
- **Почему это важно:** Данные, приходящие из внешних источников (например, через `fetch` и `JSON.parse`), по умолчанию имеют тип `string`. Поскольку `UUID` является узким типом с брендированием, TypeScript не позволит присвоить обычную строку переменной типа `UUID` без явного приведения типов (`as UUID`) или использования функции-защитника (type guard).
- **Сценарий проявления:** Если в сетевом слое или сервисах данные из API будут просто присвоены объектам типов `Event` или `Period`, возникнет ошибка компиляции. Если же будет использовано принудительное приведение (`as UUID`), существует риск, что в рантайме в систему попадут строки, не соответствующие формату `${string}-${string}-${string}-${string}-${string}`, так как брендирование работает только на этапе компиляции.
- **Необходимые условия:** Использование данных из API без предварительной валидации формата UUID через runtime-проверки (например, Zod или кастомные валидаторы).
- **Как исправить или проверить:** Проверить сетевой слой на наличие функций-валидаторов, которые подтверждают соответствие строки формату UUID перед приведением её к типу `UUID`.
- **Дословный фрагмент:**

```text
export type UUID = `${string}-${string}-${string}-${string}-${string}` & { readonly __brand: 'UUID' };
```
