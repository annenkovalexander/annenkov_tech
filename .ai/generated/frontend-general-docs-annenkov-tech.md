Данное приложение предназначено для визуализации и управления событиями в различных временных периодах. Основные сценарии включают просмотр списков событий с пагинацией, переключение между временными отрезками через специализированные контроллеры и навигацию по структуре периодов.

Архитектура фронтенда разделена на слои представления, бизнес-логики и управления состоянием. Пользовательский интерфейс состоит из базовых UI-компонентов и виджетов (списки карточек событий, элементы управления периодами). 

Состояние приложения хранится в Redux-сторе. Отдельный слайс содержит данные о текущем активном периоде, общем списке доступных периодов и заголовках страниц. Слой сервисов обеспечивает доступ к типам данных и управляет логикой обновления состояния.

# Архитектура фронтенда

## Общая структура

Архитектура фронтенда базируется на разделении ответственности между слоями представления и управления данными. Визуальная часть приложения изолирована от логики обработки информации при взаимодействии с временными периодами и событиями.

## Интерфейсные слои

Интерфейс имеет иерархическую структуру:
*   **Нижний уровень**: UI-примитивы, обеспечивающие единообразие элементов управления.
*   **Средний уровень**: Функциональные блоки (списки событий, контроллеры периодов, элементы пагинации), инкапсулирующие пользовательские действия.
*   **Верхний уровень**: Экраны, объединяющие функциональные блоки для реализации сценариев навигации.

## Данные и состояние

Управление данными реализовано через централизованное хранилище состояний. В нем хранится информация о текущем активном периоде, доступных временных отрезках и заголовках страниц. При смене периода обновляются список отображаемых событий и текстовые индикаторы в верхней части приложения.

## Сетевое взаимодействие и типы

Общие структуры типов определены в сервисном слое для обеспечения согласованности данных. Логика обновления состояния и сетевые запросы вынесены в специализированные модули, отделенные от компонентов отображения. Интерфейс отвечает за визуализацию текущего состояния, а бизнес-логика по обновлению данных сосредоточена в слое сервисов.

## Основные пользовательские сценарии

### Просмотр списка событий
Просмотр списка событий в виде карточек. Переключение между страницами списка реализовано через систему пагинации.

### Управление временными периодами
Переключение между временными отрезками с помощью специализированных контроллеров. Выбор периода изменяет набор отображаемых событий и обновляет заголовок текущей страницы.

### Навигация по структуре периодов
Взаимодействие с элементами периодов для перехода к нужным временным интервалам, фильтрации информации и визуализации распределения событий во времени.

## Типы данных и контракты

Приложение использует данные о временных периодах и событиях. Основные сущности включают:
*   список доступных интервалов времени;
*   текущий активный период;
*   заголовки страниц.

## Состояние и асинхронные операции

Данные хранятся в области состояния `periods`. В ней определены следующие поля:
*   `periods`: список всех доступных периодов;
*   `currentPeriod`: текущий активный период;
*   `pageTitle`: текстовое значение заголовка страницы.

## API и синхронизация

Взаимодействие с данными осуществляется через сервисный слой, который изолирует сетевые запросы от компонентов отображения. Данные из сетевых ответов записываются в области состояния, после чего компоненты обновляют визуальное представление.

## Поддержка пользовательских потоков

Синхронизация активного периода и заголовка страницы обеспечивает согласованность информации при навигации по временной шкале, просмотре списков событий и переключении между отрезками.

## Страницы и основные интерфейсные блоки

### Основные страницы
Приложение реализовано в виде главной страницы, которая объединяет функции просмотра списков событий, управления временными отрезками, отображения текущего контекста системы, а также инструменты навигации и фильтрации.

### Крупные интерфейсные блоки
*   **Блоки отображения событий**: список карточек событий (`EventCardList`).
*   **Контроллеры временных периодов**: элементы управления периодами (`PeriodControls`) и блоки представления периодов (`Period`).
*   **Индикаторы контекста**: текстовые блоки заголовков (`PeriodTitle`, `Title`).
*   **Навигационные элементы**: панель пагинации (`Pagination`).
*   **Базовые UI-элементы**: графические примитивы (линии, круги, прямоугольники).

### Связь с пользовательскими сценариями
*   **Просмотр списка событий**: `EventCardList` -> `Pagination`.
*   **Управление временными периодами**: `PeriodControls` -> обновление списка событий и текста в блоке заголовка страницы.
*   **Навигация по структуре периодов**: взаимодействие с элементами `Period` для изменения временного контекста и визуализации распределения событий.

## Особенности технической реализации

Ответственность распределена между слоями представления, бизнес-логики и управления состоянием. Интерфейс состоит из базовых UI-компонентов и функциональных виджетов. Слой сервисов отделен от визуальной части и управляет обновлением данных.

Доменные сущности описаны общими структурами типов в сервисном слое. Эти типы используются для описания временных периодов и событий во всех частях приложения.

Состояние организовано в виде хранилища с областью `periods`, содержащей данные о доступных периодах, активном периоде и заголовке страницы.

Сетевые операции реализованы в API-слое в составе сервисов, что изолирует запросы от представления и состояния.

## Расширение и сопровождение

Добавление новых интерфейсных решений осуществляется по следующим уровням:
*   новые экраны -> страницы;
*   переиспользуемые блоки -> виджеты;
*   пользовательские действия и логика -> функциональные модули.

Расширение предметной области включает изменение доменных типов, API-операций и состояния. Новые типы данных добавляются в сервисном слое согласно существующим контрактам. Операции API связываются с асинхронной логикой и областями состояния.

Путь изучения проекта: Доменные типы -> API-операции -> Состояние -> Thunk-операции -> Селекторы.
Цепочка передачи данных: Сетевая операция -> Сервисная логика -> Хранилище -> Компоненты интерфейса.
