*   **Верхний уровень**: Экраны, объединяющие функциональные блоки для реализации сценариев навигации.

## Сетевое взаимодействие и типы

Интерфейс отвечает за визуализацию текущего состояния, а бизнес-логика по обновлению данных сосредоточена в слое сервисов.

### 2. Утечка памяти при смене активного периода (Event Listeners)
- **Приоритет:** High
- **Тип:** подтверждённая ошибка
- **Что обнаружено:** В хуке `useGSAP` создаются обработчики событий через функцию `handleDotClick`, которая возвращает новую функцию при каждом вызове. 
- **Почему это важно:** Метод `removeEventListener` требует передачи ссылки на ту же самую функцию, которая была передана в `addEventListener`. Поскольку `handleDotClick(el, index)` генерирует новый экземпляр функции при каждом рендере/выполнении эффекта, старые обработчики никогда не удаляются из DOM-элементов.
- **Сценарий проявления:** При каждом изменении `currentPeriod` (зависимость в `useGSAP`) на каждый элемент в `refsArray` будет вешаться новый дублирующий обработчик клика. После нескольких переключений периодов один клик по точке вызовет множество одновременных Dispatch-действий.
- **Необходимые условия:** Изменение состояния `currentPeriod`, приводящее к перезапуску эффекта `useGSAP`.
- **Как исправить или проверить:** Использовать `useCallback` для `handleDotClick` или делегирование событий на контейнер.
- **Дословный фрагмент:**
```text
    useGSAP((context, contextSafe) => {
        console.log("useGSAP refsArray: ", refsArray);
        if (!pathRef.current) return;
        refsArray.current.forEach((el, index) => {
            el.element.addEventListener('click', contextSafe!(handleDotClick(el, index)));
            
        })
        return () => {
            refsArray.current.forEach((el, index) => {
                el.element.removeEventListener('click', contextSafe!(handleDotClick(el, index)));
            })
        }
    },{ scope: container, dependencies: [currentPeriod]})
```

### 4. Избыточный перезапуск эффекта при каждом рендере

- **Основная ответственность**: Хранение и обновление данных о доступных временных интервалах, отслеживание текущего активного периода и предоставление селекторов для получения данных о событиях и заголовках.
- **Взаимодействующие слои**: Слой управления состоянием (Redux), слой сервисов (импорт мок-данных).
- **Общее качество**: Код структурирован согласно стандартам Redux Toolkit, однако содержит риски рантайм-ошибок из-за отсутствия валидации входных данных и использования смешанной системы индексации.

Подтверждённых критических проблем по представленному коду не найдено.

# Ошибки и проблемы

### 1. Отсутствие проверки границ при смене периода
- **Приоритет**: High
- **Тип**: подтверждённая ошибка
- **Что обнаружено**: В редьюсере `periodChange` значение `currentPeriod` обновляется без проверки на соответствие фактическому количеству элементов в массиве `periods`. 
- **Почему это важно**: Поскольку селекторы используют `currentPeriod` для прямого доступа к элементам массива по индексу, установка значения за пределами диапазона $[1, periods.length]$ приведет к попытке обращения к свойству `undefined`, что вызовет падение приложения (Runtime Error).
- **Сценарий проявления**: Если вызывающий код передаст в `periodChange` индекс, который больше длины массива `periods` или меньше 1 (например, "999" или "-1"), приложение упадет при выполнении любого из селекторов, таких как `getPeriodTitle`.
- **Необходимые условия**: Вызов экшена `periodChange` с `payload.periodIndex`, который после преобразования в число выходит за границы массива `periods`.
- **Как исправить или проверить**: Добавить проверку в редьюсере: обновлять `state.currentPeriod` только в том случае, если полученное число находится в диапазоне от 1 до `state.periods.length`.
- **Дословный фрагмент**:
```ts
        periodChange: (state: typeof initialState, action: PayloadAction<PeriodIndex>) => {
            console.log("periodChange payload: ", action);
            state.currentPeriod = Number(action.payload.periodIndex)
        },
```

### 2. Оставленные отладочные логи в продакшн-коде
- **Приоритет**: Low
- **Тип**: улучшение
- **Что обнаружено**: В коде присутствуют вызовы `console.log`.
- **Почему это важно**: Загрязнение консоли браузера лишней информацией, что считается плохой практикой в финальном коде.
- **Сценарий проявления**: При каждом изменении периода или вызове селектора `getDots` в консоль выводятся данные.
- **Необходимые условия**: Запуск приложения в браузере с открытой панелью разработчика.
- **Как исправить или проверить**: Удалить все вызовы `console.log`.
- **Дословный фрагмент**:
```ts
            console.log("periodChange payload: ", action);
```
и
```ts
            console.log("circlePeriods: ", circlePeriods);
```

# Несоответствия с проектом

- **Архитектурные границы**: В файле наблюдается смешение ответственности: бизнес-логика (расчет "точек" в селекторе `getDots`) находится непосредственно в слайсе. Согласно документации, слой сервисов должен управлять логикой обновления состояния. Хотя RTK selectors допускают вычисления, перенос сложной трансформации данных из слайса в отдельный файл селекторов или сервис улучшил бы тестируемость.
