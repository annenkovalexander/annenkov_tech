Приложение предназначено для визуализации и навигации по событиям в рамках временных периодов. Основные сценарии включают просмотр списка событий через карточки, переключение между временными отрезками с помощью пагинации и управление отображением текущего периода.

Архитектура фронтенда основана на послойном принципе: уровень страниц, библиотека общих UI-компонентов и слой сервисов. Взаимодействие с бэкендом реализовано через API-сервисы для получения данных о событиях.

Управление состоянием приложения осуществляется с помощью Redux. Состояние разделено на функциональные слайсы: данные заголовка (сведения о пользователе и его роли) и данные периодов (активный отрезок времени, заголовок страницы).

# Архитектура фронтенда

## Общая структура
Приложение использует послойную архитектуру с разделением ответственности между представлением, управлением состоянием и сетевым взаимодействием. 

## Интерфейсные слои
Верхний уровень интерфейса составляют страницы (композиционные центры), которые определяют структуру экранов и расположение функциональных блоков. Блоки разделены на два типа:
* сложные компоненты-модули (списки событий, элементы управления периодами, навигация) для координации действий пользователя;
* базовые UI-компоненты для визуального отображения элементов.

## Данные и состояние
Состояние приложения организовано централизованно. Логика разделена на две области: управление данными профиля пользователя (имя, роль, описание) и управление контекстом навигации (текущий временной отрезок, список доступных периодов, заголовок страницы). При переключении временного интервала данные в заголовке и списке событий обновляются.

## Сетевое взаимодействие
Запросы к серверу вынесены в слой сервисов. Этот слой предоставляет данные о событиях модулям отображения. Асинхронные операции по загрузке данных инициируются при первичной загрузке приложения или смене периодов.

## Основные пользовательские сценарии

### Просмотр событий за период
Пользователь просматривает список событий в виде карточек, которые сгруппированы по временным интервалам. Сценарий включает изучение деталей записей в рамках текущего активного периода.

### Навигация по временным отрезкам
Переключение между временными интервалами осуществляется через инструменты пагинации и элементы управления периодами. При смене периода приложение обновляет заголовок страницы и запрашивает данные о событиях для выбранного промежутка времени.

### Работа с информацией профиля
В шапке приложения отображаются сведения о текущем пользователе: полное имя, роль и описание. Эти данные используются для идентификации уровня доступа и контекста работы в системе.

## Данные и взаимодействие с backend

## Типы данных и контракты
Используются типы данных для описания профиля пользователя (полное имя, роль, описание) и объектов временных периодов. Эти сущности определяют контекст отображения информации на страницах, используются для формирования заголовков интерфейса и наполнения информационных карточек.

## Состояние и асинхронные операции
Состояние разделено на две функциональные области:
1. Область заголовка: данные профиля пользователя (имя, роль, краткое описание).
2. Область управления временными отрезками: список доступных периодов, текущий активный период и соответствующий заголовок страницы.

Эти данные предоставляются компонентам для визуализации контекста работы.

## API и синхронизация
Взаимодействие с сервером реализовано через слой сервисов, который обеспечивает получение данных о событиях. API-вызовы используются для загрузки списков событий по выбранному временному интервалу. Результаты передаются в модули приложения для обновления экрана при инициализации системы или смене периода.

## Поддержка пользовательских потоков
Организация данных и сетевого взаимодействия поддерживает просмотр событий за период и навигацию по временной шкале. Смена временного отрезка инициирует запрос к API, после чего обновляется список карточек событий и синхронизируется заголовок страницы. Данные профиля из состояния отображаются в шапке приложения.

## Страницы и основные интерфейсные блоки

### Основные страницы
В приложении представлена основная страница (центр композиции), предназначенная для визуализации событий по временным интервалам и навигации между ними. Страница объединяет просмотр списков событий, переключение отрезков времени и отображение профиля пользователя.

### Крупные интерфейсные блоки
Интерфейс состоит из следующих блоков:
* **Шапка приложения (Header)** — отображает сведения о пользователе (полное имя, роль, описание).
* **Список карточек событий (EventCardList)** — визуализирует перечень событий за выбранный период.
* **Инструменты пагинации (Pagination)** — обеспечивают переключение между временными отрезками.
* **Панель управления периодами (PeriodControls) и Заголовок периода (PeriodTitle)** — используются для управления отображением текущего интервала и визуализации его названия.

### Связь с пользовательскими сценариями
На основной странице используется список карточек, который обновляется при взаимодействии с пагинацией и панелью управления периодами. Смена временного отрезка через блок пагинации приводит к запросу новых данных о событиях и изменению текста в заголовке периода. Блок в шапке приложения обеспечивает доступ к данным профиля пользователя независимо от выбранного интервала.

## Особенности технической реализации

Ответственность распределена между страницами (композиция экранов), функциональными модулями (координация действий) и UI-компонентами (визуальное отображение).

Доменные сущности представлены отдельными типами данных для профиля пользователя и временной структуры событий. Эти типы используются в разных частях приложения для формирования заголовков интерфейса и информационных карточек. 

Состояние включает области данных заголовка (сведения о профиле) и управления периодами (список доступных отрезков, активный период). Асинхронные операции выполняются при первичной инициализации приложения или смене периода.

API-слой содержит операции по получению данных о событиях для выбранного временного интервала. Сетевые операции отделены от представления и состояния. Данное распределение используется при поэтапном развитии проекта.

## Расширение и сопровождение

Новые интерфейсные решения добавляются через существующие уровни: новые экраны — в страницы, переиспользуемые блоки — в компоненты, логика действий — в функциональные модули.

Расширение предметной области осуществляется через обновление доменных типов, API-операций и состояния. Новые типы данных добавляются согласно существующим контрактам. Новые операции API связываются с соответствующей асинхронной логикой и областями состояния.

При анализе проекта рекомендуется изучить путь данных по цепочке: сетевая операция -> асинхронная логика (thunk-операции) -> состояние (слайсы, селекторы) -> компоненты интерфейса.
